# 2026-04-17 — zip release — design

## Goal

Produce a downloadable `normalpowers-vX.Y.Z.zip` on every GitHub Release that users can extract and drag directly into Claude.ai Projects knowledge — no GitHub browsing, no copying file-by-file.

## Approach

Option B: a `scripts/build-release.sh` that produces the zip locally (locally testable), plus a thin GitHub Actions workflow that runs the script and attaches the zip to the release automatically when the maintainer clicks "Publish release."

## Section 1 — Zip contents

```
normalpowers-vX.Y.Z.zip
├── INDEX.md                                 ← LLM-facing, uploaded as knowledge
└── skills/
    ├── using-normalpowers/SKILL.md
    ├── brainstorming/SKILL.md
    ├── writing-plans/SKILL.md
    ├── following-your-plan/SKILL.md
    ├── systematic-problem-solving/
    │   ├── SKILL.md
    │   ├── root-cause-tracing.md
    │   └── defense-in-depth.md
    ├── verification-before-completion/SKILL.md
    ├── receiving-feedback/SKILL.md
    └── writing-skills/
        ├── SKILL.md
        ├── anthropic-best-practices.md
        └── persuasion-principles.md
```

- `normalpowers.md` (master prompt) is **not** included — it goes into custom instructions, not knowledge.
- `graphviz-conventions.dot` is **not** included — not a Claude knowledge file.
- Directory structure is preserved so the LLM can locate skills by folder name.

`INDEX.md` is an LLM-facing file uploaded alongside the skills. It tells the LLM: you have the normalpowers bundle loaded as knowledge; the 8 skills live in `skills/<name>/SKILL.md`; supporting reference docs live alongside their parent skill; when the master prompt says "read skill X", retrieve `skills/X/SKILL.md` from this knowledge base.

**User workflow:** download zip → extract → drag the extracted folder into Claude.ai Projects knowledge. One operation.

## Section 2 — Build script

File: `scripts/build-release.sh`

Behavior:
1. Reads version from `package.json` `.version` field (no manual input).
2. Creates `dist/` if it doesn't exist; removes any prior `dist/normalpowers-*.zip`.
3. Creates a temp staging directory.
4. Copies `skills/` into staging, preserving directory structure, excluding `graphviz-conventions.dot`.
5. Generates `INDEX.md` in staging (static content, same every release).
6. Zips staging into `dist/normalpowers-v{version}.zip`.
7. Prints a manifest of all files in the zip so the maintainer can verify contents before tagging.

Running locally produces the identical artifact that Actions will upload. Maintainer can `unzip -l dist/normalpowers-v*.zip` to verify before creating the release.

## Section 3 — GitHub Actions workflow

File: `.github/workflows/release.yml`

Trigger: `on: release: types: [published]`

Steps:
1. `actions/checkout@v4`
2. `chmod +x scripts/build-release.sh && ./scripts/build-release.sh`
3. `gh release upload ${{ github.event.release.tag_name }} dist/normalpowers-v*.zip --clobber`

Uses the automatically-available `GITHUB_TOKEN`. No secrets to configure. The zip appears as a downloadable release asset within ~30 seconds of the maintainer clicking "Publish release."

## Section 4 — README update

Add a "Download" subsection under the Claude.ai Projects install instructions. Content:

- Link to the GitHub Releases page.
- One sentence: "Download the latest `normalpowers-vX.Y.Z.zip`, extract it, and drag the extracted folder into your Claude Project's knowledge."
- Note that `normalpowers.md` (custom instructions) is a separate step, covered directly above.

This makes the zip the recommended install path for Claude.ai Projects — one drag operation instead of uploading skill files individually from GitHub.
